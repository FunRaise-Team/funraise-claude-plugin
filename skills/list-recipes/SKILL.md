# 列出所有食譜，選一份來做

食譜依**連線**分開存放：個人的 Funraise 連接器看得到「個人食譜」，團隊的連接器看得到那個團隊的「團隊食譜」，每一條連線也都看得到「官方食譜」。使用者可能同時接了好幾條 Funraise 連接器，所以要把每一條的食譜都收齊，合成一份清單。

## 1. 收齊每一條連線的食譜

在可用工具裡找名稱結尾是 `recipes__list_recipes` 的工具。每一條帶這支工具的 Funraise 連接器都呼叫一次（各用自己那條連接器上的工具）。

- **一支都找不到**：這條連線還沒有食譜功能。告訴使用者：食譜功能目前只在部分連線開放；團隊食譜要用團隊的連接器（不是 Directory 的通用網址）；可以到 https://app.mcp.funraise.ai/admin/ 查看自己的連接器。然後停下來。
- 記下每一份食譜**來自哪一條連接器**：之後取出它時，要用同一條連接器上的工具。
- **官方食譜每一條連線都會回傳同一批**：依 `recipe_id` 去掉重複，只列一次（取出時用哪一條連線都可以）。

## 2. 合成一份清單，讓使用者選

依食譜集分組，順序是：個人食譜 → 各團隊食譜 → 官方食譜。每一份寫：用途、第幾版、最後更新日期；有需要注意的狀態時加註（上次做菜有未處理的問題、這條連線缺少需要的資料源、需要重新驗證）。

例：

```
要用哪一份食譜？

個人食譜
1. 某區新成屋預售行情整理（第 2 版，10/3 更新）

方睿科技股份有限公司 / Data Team 團隊食譜
2. 找出某行政區臨路面坐北朝南、有出租物件的辦公大樓，產出盤點報告（第 4 版，10/7 更新）
3. 查某行政區的辦公大樓，列出前 N 棟的名稱與門牌（第 5 版，10/6 更新）· 上次有 1 個問題未處理

官方食譜
4. 商辦大樓周邊重點企業盤點（第 1 版，9/30 更新）
```

- 你的介面有讓使用者點選的提問工具（例如 Claude Code 的 AskUserQuestion）就用它；選項太多放不下時，先問要看哪一份食譜集，再列那一組。沒有提問工具時，列出編號、請使用者回覆數字。
- **全部只有一份食譜**時，直接告訴使用者是哪一份、問他要不要用它，不用列選單。
- **一份食譜都沒有**：說明怎麼新增 —— 用 Funraise 完成一段工作後，說「把這次的做法存起來」（或用 `/save-recipe`）。
- 同一個用途同時出現在個人與團隊時，兩份都列出來，標明各在哪一份食譜集。
- 有些介面會在 `recipes__list_recipes` 的結果上顯示食譜卡片；使用者直接點了卡片上的按鈕時，照卡片送來的訊息取出那一份，不用再問一次。
- 使用者只是想看有哪些食譜、還沒打算做菜，列完就停，等他選。

## 3. 取出選中的那一份

用那份食譜**所在的那一條連接器**上的 `recipes__get_recipe`，帶它的 `recipe_id`。

- 取出後**照食譜第 0 節**：逐一向使用者確認每個變數（表單或對話中預填的是上次的範例值，不是這次的食材），清點附件。使用者確認之前不要開始做菜。
- 這條連線缺少食譜需要的資料源時，`recipes__get_recipe` 會說明；轉告使用者，並請他改用有那個資料源的連線，或到後台開啟。
- 做完之後怎麼交出成品、怎麼回報缺口，寫在 `recipes__get_recipe` 的說明與食譜第 4 節裡，照著做。
