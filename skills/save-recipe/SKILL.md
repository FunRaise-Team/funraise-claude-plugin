# 把這次的做法存成食譜

食譜存在哪裡，由**連線**決定：個人的 Funraise 連接器存「個人食譜」，團隊的連接器存那個團隊的「團隊食譜」。使用者可能同時接了好幾條 Funraise 連接器，所以先弄清楚有哪些地方可以存，再讓使用者選。

## 1. 找出可以存的地方

在可用工具裡找名稱結尾是 `recipes__save_recipe` 的工具。每一條帶這支工具的 Funraise 連接器，就是一個可以存的地方。

- **一支都找不到**：這條連線還沒有食譜功能。告訴使用者：食譜功能目前只在部分連線開放；團隊食譜要用團隊的連接器（不是 Directory 的通用網址）；可以到 https://app.mcp.funraise.ai/admin/ 查看自己的連接器。然後停下來，**不要假裝已經存好，也不要改成把內容貼在對話裡當成存檔。**
- **找得到**：對每一條帶食譜工具的連接器，各呼叫一次同一條連接器上的 `recipes__list_recipes`。回應會寫明這是哪一份食譜集（例如「個人食譜」「某公司 / 某團隊 團隊食譜」），也會列出裡面已經有的食譜與版本。

## 2. 確認要存的是哪一件工作

從對話找出要存的那段工作：用了哪些 Funraise 工具、使用者給了哪些條件、最後交出什麼成品。

- 對話裡沒有用 Funraise 工具完成的工作，或有好幾件看不出要存哪一件：先問使用者，不要猜。
- 用一句話寫出這份食譜的**用途**（例如「找出某行政區臨路面坐北朝南、有出租物件的辦公大樓，產出盤點報告」），後面的比對與選單都用它。

## 3. 讓使用者選：存到哪裡、新增或更新

把「存到哪裡」與「新增還是更新」合成**一個選單**，一次問完：

- 每一個可以存的地方，各列一個「新增一份」。
- 第 1 步列出的食譜中，用途和這次工作相近的，各列一個「更新『用途』（第 N 版 → 第 N+1 版）」。只列相近的，不要把所有食譜都列出來。
- 選項文字寫食譜集的名稱（第 1 步回應裡的那個名稱），不要寫連接器的技術名稱。

例：

```
要把這次的做法存到哪裡？
1. 個人食譜：新增一份
2. Data Team 團隊食譜：新增一份
3. Data Team 團隊食譜：更新「找出某行政區臨路面坐北朝南…」（第 4 版 → 第 5 版）
```

- 你的介面有讓使用者點選的提問工具（例如 Claude Code 的 AskUserQuestion）就用它；沒有的話，列出編號、請使用者回覆數字。
- **只有一個地方可以存、而且沒有相近的食譜**時，不用問這一題，直接到第 4 步。
- 同一個用途在個人與團隊都已經有時，兩份都列出來，標明各在哪一份食譜集，讓使用者選。

## 4. 存檔前給使用者看重點

存檔前用幾行列出：用途、要使用者提供的食材（變數與附件，附這次的範例值）、步驟數、成品是什麼。請使用者確認或修改。

- **存到團隊食譜時**，提醒：範例值、使用者的原話與附件連結，全團隊的人都看得到；附件若是個人的連結，請使用者先開放給團隊。
- 使用者要改，就照他說的改，再給他看一次。

## 5. 存檔

在使用者選的那一條連接器上呼叫 `recipes__save_recipe`。整理食譜的原則（只寫成功過的步驟、工具寫全名、每個要使用者提供的東西都寫成食材、範例值取自這次對話……）寫在那支工具的說明裡，照著做。

- **新增**：不帶 `recipe_id`。
- **更新**：帶那份食譜的 `recipe_id`，並把 `based_on_version` 設成第 1 步看到的版本；`note` 用一句話寫這一版改了什麼。
- **被拒絕**（回應有 `accepted: false` 或逐條列出的問題）：照問題逐條修正後再送一次。修不了的（例如需要的資料源這條連線沒有開）告訴使用者，不要硬存。
- **版本衝突**（有人在這之間存了新版）：告訴使用者是誰、什麼時候存了第幾版，問他要以那一版為基礎重新整理，還是另存一份。
- **額度已滿**：轉告回應裡的說明與後台連結。

## 6. 回報

告訴使用者：存到了哪一份食譜集、是新增還是第幾版，附上回應裡的後台連結。最後提醒下次怎麼用：說「列出我的食譜」（或用 `/list-recipes`），選一份、填入這次的條件，就能照同樣的做法再做一次。
